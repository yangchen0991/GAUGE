## 一、产品范围

**GAUGE · ZCode / Codex 双平台综合监控台**：主面板、桌面贴纸、托盘三入口全局联动；顶部平台选择 `GAUGE [ZCode/Codex] 时间范围 项目筛选 刷新状态`。

切换规则：

| 场景 | 预期行为 |
|---|---|
| 主面板选择 Codex | 主面板、贴纸、托盘一起切换 |
| 贴纸或托盘切换平台 | 同步更新其他已打开窗口 |
| 关闭后重新启动 | 恢复上次选择的平台 |
| 首次使用升级版 | 默认保留现有 ZCode |
| 某平台没有数据 | 显示该平台的引导或空状态 |
| 某平台读取失败 | 留在该平台，显示错误和最后成功更新时间 |
| 快速连续切换 | 只显示最后选中的平台，丢弃过时结果 |
| 切换回来 | 恢复该平台各自的筛选条件和页面位置 |

全局联动，不做"贴纸与主面板分别显示不同平台"模式。浏览器单独打开导出 HTML = 快照模式，不通过网页控制桌面贴纸。

## 二、Codex 页面规划：五个主要看板 + 数据与环境说明

每项数据标明：已接入 / 条件接入 / 仅展示元数据 / 不展示及原因（避免无声遗漏）。

| 页面 | 主要内容 | 可展开内容 |
|---|---|---|
| 总览 | 今日及所选时段 Token、任务活动、异常、额度、趋势 | 最近任务、项目排行、模型排行、数据完整性 |
| 用量分析 | 输入/输出/缓存/推理 Token 与时间趋势 | 按项目、模型、Provider、Agent 角色、任务分析 |
| 项目视图 | 放在总览和用量分析中，并提供项目详情 | 显式项目关联优先；缺省按工作目录匹配标"目录推断"；无法确定归"未归属" |
| 任务 | 任务列表、历史状态、最后活动、耗时、用量 | 回合时间线、工具事件、错误、Git 信息、目标与预算 |
| Agent 协作 | 主任务与子 Agent 树形关系 | 角色、模型记录、父子关系、自身用量与整组用量 |
| 工具与异常 | 工具类型、调用次数、成功/失败、耗时 | 命令、文件修改、MCP、搜索、异常分类与关联任务 |
| 数据与环境 | 数据源、更新时间、覆盖范围、读取状态 | 本地版本记录、配置声明、Skills/插件/MCP 清单及兼容性 |

细化原则：
- 模型视图：记录中的模型与配置默认值分别展示。
- 目标与预算入任务详情；只有存在预算时才显示比例。
- 自动化/队列/记忆处理状态纳入数据能力清单；未找到数据 ≠ 功能不存在。
- Skills/插件/MCP 区分"已安装或已配置"与"观察到实际调用"。
- 任务详情统一入口：点开任务查看回合、用量、子 Agent、工具与异常。

## 三、桌面贴纸规划

保留紧凑/展开布局，Codex 模式同视觉体系。

| 区域 | 紧凑布局 | 展开布局补充 |
|---|---|---|
| 平台与状态 | Codex 标识、数据更新时间、读取状态 | 当前数据来源及覆盖提示 |
| 核心指标 | 今日 Token、任务活动概况 | 输入、输出、缓存和推理分项 |
| 账号额度 | 5 小时及每周窗口、重置倒计时 | 来源、采集时间、是否为历史快照 |
| 趋势 | 最近七天用量 | 更多趋势指标切换 |
| 任务 | 最近活动任务摘要 | 最近任务列表、异常和子 Agent 摘要 |
| 操作 | 切换平台、刷新、打开主面板 | 点击指标进入对应详情 |

显示原则：读不到额度显示"暂不可用"不显示 0%；只有历史快照时明确显示快照时间；未证明实时可靠时用"最近活动"不标"正在运行"；点击贴纸任务/异常 → 主面板切到同平台并定位；平台切换通过更新数据完成，保持同一贴纸窗口。

## 四、统计口径（详见 docs/阶段1，以契约为准）

Token 字段统一模型、防重复计数总则、线程标识与恢复语义、状态与耗时口径、异常三层分类、请求数定义、额度与费用三层分离。

## 五、数据与缓存策略

SQLite mode=ro 短事务；rollout 按文件 mtime/大小增量；缓存在 GAUGE 自有数据目录；平台切换优先显示本平台缓存再后台更新；重复刷新合并执行；数据源升级字段变化时禁用受影响指标并给出原因。

三个独立能力分别验收：历史读取 / 日志增量观察 / 官方实时接口（app-server）。账号接入只走受支持方式；不复制认证文件、不逆向内部端口；直接读取失败可展示带时间标记的快照，但不包装为实时。

## 七、验收场景（阶段5 全量执行）

- 统计正确性：重复事件、累计快照、跨日、恢复、分叉、子任务、部分日志缺失
- 读取健壮性：数据库忙、来源不存在、字段变化、日志截断、缓存损坏
- 切换一致性：快速切换、刷新途中切换、窗口关闭重开、应用重启
- ZCode 回归：原有统计口径、页面、贴纸和配置行为保持正确
- Codex 页面：筛选、排行、详情与总览之间数据一致
- Windows 实际窗口：紧凑与展开、拖动、置顶、穿透、钉桌面、多显示器及不同缩放
- 性能：首次索引、后续刷新、切换响应和内存占用实测
- 打包产物：候选 EXE 上验证资源路径、子进程、缓存、刷新和平台联动

历史拖动/缩放/圆角问题作为回归检查项；执行前核对当前表现，不假定已修好或仍存在。

实施分工：Luna 按明确文件边界执行；复杂统计与状态不变量由 Astra 判断；完成后独立 Luna Reviewer 审查，再进 Astra 最终验收；审查拆数据正确性/桌面联动/界面与产物分片。

最终交付：双平台主面板 + 联动贴纸与托盘 + 共享数据与缓存模块 + 测试结果 + Windows 候选构建 + 数据口径和使用说明。
