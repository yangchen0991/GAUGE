# GAUGE 双平台 · 阶段 1 统计口径与数据契约（2026-09-21）

定位：阶段 1 产出。基于阶段 0 数据能力清单与当日定向取证（8 项，全部实测，证据摘录见第 4 节），冻结双平台统计口径与统一数据结构。阶段 2 的 gauge_data 实现、阶段 3 的页面指标、阶段 5 的验收测试都以本文为准；实现与本文冲突时以本文为准修订实现。

## 1. 口径裁决

### 1.1 Token 字段统一模型

| 统一字段 | Codex 来源（rollout） | ZCode 来源（db.sqlite） | 语义 |
|---|---|---|---|
| input_total | usage.input_tokens | model_usage.input_tokens | 总输入，已含缓存读取 |
| cached_input | usage.cached_input_tokens | cache_read_input_tokens | 已含于 input_total 的缓存命中 |
| cache_write_input | usage.cache_write_input_tokens | cache_creation_input_tokens | 缓存写入（ZCode 实测全表 0 行 >0，实现仍读原列） |
| output_total | usage.output_tokens | output_tokens | Codex 已含 reasoning；ZCode 不含 |
| reasoning_output | usage.reasoning_output_tokens | reasoning_tokens | Codex ⊆ output_total；ZCode 为加法独立量 |
| total_native | usage.total_tokens | computed_total_tokens | 平台原生：Codex=in+out；ZCode=in+out+reasoning |
| io_total | input_total + output_total | input_total + output_total | 唯一允许跨平台比较的总量 |

fresh_input（非缓存输入）= input_total − cached_input，两平台同义。

证据：Codex 3 样本 total=in+out 精确成立且 reasoning 恒 ≤ output；ZCode 全表 11,487 行 computed_total=in+out+reasoning 差异数 0（阶段 0）。
禁令：Codex 侧 output 与 reasoning 相加即重复计数；ZCode 的 total_native 不得当 io_total 做跨平台比较（虚高 reasoning 部分）。

### 1.2 聚合与去重总则（防重复计数清单）

1. Codex 三级累计（usage=单次响应 / turn_token_usage / thread_token_usage）并列于同一记录：聚合只用 usage 级求和；turn/thread 级仅作展示与交叉校验。
2. token_count 事件与 token_usage_record 是同一数据的两种投影（实测同 turn 末条 record.usage 与 info.last_token_usage 逐字段相等）：token 计数取 record，rate_limits 与 model_context_window 取 token_count 事件；两边永不相加。
3. 旧格式 rollout（约 2026-09 之前）无 token_usage_record：per-response 用量取 token_count.info.last_token_usage（与 record 等价）。
4. ZCode turn_usage 是 model_usage 按 turn 的聚合投影（3 个共享 turn 五列 SUM 逐项相等；覆盖非完全：仅 model_usage 有的 turn 6 个、仅 turn_usage 有的 9 个、model_usage 另有 23 行 turn_id 为 NULL）：同一聚合中二选一。ZCode 规范源 = model_usage（请求级，保明细与既有回归），turn_usage 仅作校验或后续优化，禁止混用；对账时单侧 turn 与 NULL turn_id 属已知差异，不计为数据错误。
5. Codex threads.tokens_used = 该线程最新 rollout 文件末条累计（实测 29,636,982 精确等于最新文件末值，resume 不继承，前文件 71,675,471 不含在内）。因此：展示"线程累计（最新段）"用 threads.tokens_used 或最新文件末值；展示"线程生命周期总量"必须 Σ 该线程全部文件的 per-response 用量。两个口径并存、必须标注。2026-09-21 注：当前 rollout 扫描源仅含每线程最新文件（threads.rollout_path），生命周期=Σ全部文件口径暂缺数据来源，本指标暂缓实现（真实 resume 线程本机仅 1 个且旧段在典型统计窗口外）；扫描源扩展后启用。
6. ZCode 子代理用量已按子会话行归属（session.parent_id 子会话 408 个、其中 398 个有用量行）："仅顶层会话"统计会漏子代理 token；任何"主任务自身"口径必须显式声明是否含子树。

### 1.3 线程标识、恢复与派生

- Codex 线程标识 = session_meta.payload.session_id（跨文件持续）；payload.id 每文件唯一，不可用作线程 id。resume 产生带 _<id> 后缀的新文件；state_5.threads.rollout_path 指向最新文件，threads 行按 id 唯一。
- resume 不继承累计（唯一实测 resume 对：前文件末值 71,675,471，后文件首值 30,717 从零重启）。26 个多文件线程中 25 个是"1 主文件 + N 个 spawn 子代理文件"，真正 resume 对仅 1 个。
- fork：无实际数据（全库仅工具定义文本中出现 fork 字样），不设 fork 指标；派生关系只有 spawn（thread_spawn_edges）。
- ZCode 父子 = session.parent_id（task_type=subagent_child / selection_side_chat）。

### 1.4 状态与耗时

- Codex 回合状态：completed 631 / interrupted 163 / failed 87 / inProgress 9（890 行，取证时点快照，实现不得硬编码）；duration_ms 与 (completed_at−started_at)×1000 精确吻合；completed_at 与 duration_ms 为 NULL 的恰为 inProgress 回合。
- 时间单位：Codex thread_turns.started_at/completed_at、logs_2.ts、rate_limits.resets_at 为 epoch 秒（实测值域 1.79e9 验证）；thread_items.created_at_ms 与 threads 时间列为 epoch 毫秒（实测值域 1.79e12 验证）；rollout 行 envelope 含 timestamp 字段，实测形态为 ISO 8601 带毫秒的 UTC 字符串（样例 2026-09-20T16:17:10.035Z，envelope 另含 ordinal 序号字段）。内部表示统一为 epoch 毫秒，读取层负责换算与 UTC→本地时区呈现。
- "正在运行"只能来自 app-server 实时探针（阶段 0 冻结边界）；文件侧最高表述为"最近活动"（recency_at_ms）。
- 并行子代理耗时不得相加；如需子树耗时展示"跨度"= max(子树结束) − min(子树开始) 并明确标注为跨度。
- 回合 failed 中"额度耗尽"类（error_json 实测含 "You have no credits remaining"）单列为系统性失败，不与代码失败混计。

### 1.5 异常分类

三层独立计数、互不替代、不相加：
1. 回合失败：thread_turns.status=failed，按 error_json 归类（usage_exhausted / stream_error / other）。
2. 工具失败：条目级（thread_items 中 commandExecution / mcpToolCall 等的状态与错误字段；ZCode tool_usage.error_type）。
3. 诊断日志错误：logs_2 level=ERROR 按 target 分组计数。

### 1.6 请求数

Codex 模型请求数 = distinct response_id（token_usage_record 计数）；ZCode = model_usage 行数。回合数、工具调用数不得充当请求数。

### 1.7 额度与费用

- 额度是账号范围，不随项目筛选变化。Codex 历史额度曲线 = token_count 事件 rate_limits 快照点（实测 1207 个事件中 1206 个携带）；resets_at 为 epoch 秒；primary=5 小时窗（window_minutes=300）、secondary=7 天窗（10080）；plan_type 实测 plus 与 null 并存；credits.balance 为字符串。
- 读不到额度显示"暂不可用"，绝不显示 0%；credits.has_credits=false 与"no credits"回合失败互证。
- 费用三层分开呈现：订阅额度（账号级）/ token 用量（本平台统计）/ 金额估算。金额估算仅 ZCode 提供（官方目录价）；Codex 为订阅制，不做金额估算。

## 3. 统一数据结构

导出契约与已冻结的 test_dual_export.py 对齐：collect_codex() 返回 platform / available / status / generated_at / generated_at_ms / threads / turns / usage / tools / edges / projects / goals / quota / coverage / warnings / environment / diagnostics / sources。

### 3.1 归一化记录（gauge_data 内部与导出共用）

> 2026-09-21 审查后按实现自洽方向修订命名，语义不变（裁决记录见 orbital/DECISIONS.md）：字段名与单位以 gauge_data 实际输出为准。

- ThreadRecord：id、title、cwd、project_id、project_name、project_inferred、created_at、updated_at、model、provider、role、reasoning_effort、parent_id、archived、git_branch、git_sha、cli_version、recorded_tokens、status、last_activity_at（时间字段为 epoch 毫秒；rollout_path 仅作内部索引，不导出）
- TurnRecord：id、thread_id、status、started_at、completed_at、duration_ms、error_type、n_responses（该回合的 usage 记录数，2026-09-21 审查后补）
- UsageRecord：id（=response_id）、response_id、thread_id、turn_id、root_turn_id、timestamp（envelope 毫秒；缺失时回退所属回合 started_at）、model、provider、input_tokens、cached_input_tokens、cache_write_input、output_tokens、reasoning_output_tokens、total_tokens（=input+output）、derived
- ToolCallRecord：id、thread_id、turn_id、type、name、status、duration_ms、timestamp、exit_code、server
- EdgeRecord：parent_id、child_id、status
- ProjectRecord：id、name、roots[]
- GoalRecord：id、thread_id、objective（截断 120，2026-09-21 审查后补）、status、token_budget、tokens_used、time_used_seconds
- QuotaSnapshot（2026-09-21 冻结形状）：captured_at（毫秒）、source（"rollout_snapshot"）、plan_type、primary{used_percent、window_minutes、resets_at_ms}、secondary{同构}、credits{has_credits、unlimited、balance}。resets_at 源为 epoch 秒，输出统一换算为毫秒（秒/毫秒歧义按 1e11 阈值判定）；credits 缺失容忍为 has_credits=false、unlimited=false、balance=null；limit_id=premium 等变体 primary/secondary 为 null 时整体跳过，不产出半残快照
- 环境与诊断（实现现状）：environment{codex_home、sqlite_home、config_files、config_fields、skills_files、plugins、mcp_names、automations、memories、queue}；diagnostics{cache_schema_version、source_read、log_counts、stale、last_success_at（stale 时为上一成功快照的 generated_at_ms）、legacy_usage}

### 3.2 ZCode 侧

保持现有 DATA 与 sidecar 顶层形状不变（回归约束：ZCode 单平台全部既有数字不变）。其字段到统一 token 模型的映射按 1.1 执行；platforms.codex 的加入不改动 platforms.zcode 的旧顶层字段。

### 3.3 导出载荷

collect_codex() 各数组键即 3.1 对应记录数组；quota 为 QuotaSnapshot 或 null；coverage={processed_files、total_files、pending_bytes、usage_records、complete}；warnings 为字符串数组；sources 记录各数据源路径与缓存位置。

> 2026-09-21 审查后按实现自洽方向修订命名，语义不变：coverage 键名由 files_indexed/records_parsed/gaps[] 修订为 processed_files/usage_records 等实现现状。
